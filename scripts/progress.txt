## Codebase Patterns
- Java/Maven not available in this container — backend tests cannot be run directly; verify manually or in CI
- Frontend TypeScript check: `/workspace/frontend/node_modules/.bin/tsc --noEmit --project /workspace/frontend/tsconfig.json`
- Frontend has pre-existing lint errors in `LiquidEther.jsx`, `Header.tsx`, `app/page.tsx`, `app/curriculum/page.tsx` — do not fail on those
- Admin JWT stored in cookie named `admin_token`; `setAuthToken`/`getAuthToken`/`clearAuthToken` helpers live in `frontend/lib/adminApi.ts`
- `authFetch` in `adminApi.ts` auto-adds `Authorization: Bearer <token>` header; skips `Content-Type: application/json` for FormData (multipart uploads)
- Admin API file: `frontend/lib/adminApi.ts` — imports nothing from `api.ts` to keep concerns separated
- Spring Boot 4 uses `SecurityFilterChain` bean pattern, NOT `WebSecurityConfigurerAdapter` (deprecated)
- jjwt 0.12.x uses `Jwts.builder()` / `Jwts.parser()` API (not `parserBuilder()` which is 0.11.x)
- prd.json lives at `/workspace/scripts/prd.json`; progress.txt lives at `/workspace/scripts/progress.txt`
- Admin credentials stored as env vars `ADMIN_USERNAME` / `ADMIN_PASSWORD` in application.properties (same pattern as JWT_SECRET)
- Auth endpoint: `POST /api/auth/login` — body `{username, password}`, returns `{token}` or 401
- Spring Security CORS: define `CorsConfigurationSource` bean in `SecurityConfig` + use `.cors(Customizer.withDefaults())` — this takes precedence over `WebMvcConfigurer.addCorsMappings()`
- Security rule order: `/api/auth/login` permitAll → GET /api/** permitAll → GET /uploads/** permitAll → everything else authenticated
- JWT filter is in `security` package; `SecurityConfig` is in `config` package (follows existing package conventions)
- Static file serving: configure in `WebConfig.addResourceHandlers()` using `file:` prefix with absolute path; add corresponding permitAll rule in `SecurityConfig`
- `MaxUploadSizeExceededException` is thrown by Spring before reaching the controller — must handle in `@RestControllerAdvice` (GlobalExceptionHandler), not in the controller method
- Image upload: validate `MultipartFile.getContentType()` for allowed MIME types; use `UUID.randomUUID()` for filenames to avoid collisions
